## [Unreleased]

### Added
- Startup sweep for order and account mail that was queued and never recorded. A crash after an order confirmation or pickup-request email is handed off, or during welcome, set-password, or password-reset mail, leaves a `mail_outbox` row. On the next start Launchpad sends that notice once. `order_notify_log` and `account_audit_log` are the source of truth: a sent row is not sent again, and a stored sent timestamp is left alone. Each resend is written to the log as `MAIL RESEND`. A row another process has claimed is left alone until that lease is older than the drain bound plus a margin (`MAIL_SWEEP_LEASE_MARGIN_MS`, default 5 seconds), so a deploy that overlaps a draining process does not send the same notice twice. The sweep keeps running on an unref'd timer for the life of the process, and that timer stops when this process drains, so a send abandoned by a peer that was killed mid-drain is delivered after its lease expires without another restart. A tick is skipped while a sweep is already running, and a drain stops the sweep from claiming anything further. Schema setup runs once, not on every tick. Saving an order reads location access on that order's own database transaction, so the sweep's writes cannot stall the request behind a locked connection. The timer skips a notice this process is already sending, and `claim` will not take that row again. Pickup and order confirmation reserve the notice before it is queued, and a pickup confirmation that already has `confirmation_email_sent_at` is not sent again. While the send runs, the lease is renewed. SMTP connect, greeting, and socket timeouts together stay inside the drain bound, so a slow server is finished before shutdown gives up on the send. Active rows are unique per notice (`INSERT OR IGNORE`). The sweep does not turn Email Orders on and does not change mailbox polling. `node scripts/verify-ops.js` checks a pending confirmation with no log, a pending confirmation that was already logged, a second sweep, welcome mail, a later password reset, a pickup-request email, a live lease, an expired lease, and two processes enqueueing and sending at once.
- Graceful shutdown on SIGTERM and SIGINT. The server stops accepting connections and waits for requests already being handled to finish. It does not start another poller tick. In-flight email, those requests, and the poller tick already running are given about 20 seconds (`DRAIN_TIMEOUT_MS`). If they finish, the process exits 0. If the bound expires first, the process exits non-zero. Mail that did not finish stays queued for the startup sweep. `node scripts/verify-ops.js` checks that an idle server exits 0 on SIGTERM and that a held send is abandoned inside the drain bound with a non-zero exit and delivered once on the next start.
- Managers see customer mobile numbers only for customers at their own shop. Admins still see every number. A manager with no shop sees none: an empty location is not treated as every shop for mobile numbers. Operators do not see SMS recipients. `GET /api/customers` omits `mobile_phone` unless the manager's shop matches the customer's shop, and `PUT /api/customers/:id/texting` returns HTTP 404 otherwise. Order detail omits `customer_notices` recipient on SMS rows unless the viewer is an admin or a manager whose shop matches `customer.location_id`, including when the order itself was moved to another shop. The email recipient stays. The Customers page disables Text updates when the number was withheld, and the order page shows the text recipient as hidden when it was omitted. `node scripts/verify-ops.js` checks the list, the texting update, a transferred order, a manager with no shop, and an operator.
- Email Orders security hardening. A new database leaves mailbox polling off. Customer suggestions from an exact address or a company domain stay unverified, and public mailbox domains are never used for a domain match. Convert requires stored staff confirmations for the customer, the confirmation recipient, and each attachment, plus the session CSRF token. Attachments stay quarantined unless clamd reports them clean. Magic bytes must match the extension. Encrypted files and scanner failures stay quarantined. Releasing an unscanned file is off unless `ALLOW_UNSCANNED_ATTACHMENT_EXCEPTION` is true, and then it takes an admin, a reason, and a second confirmation. `orders.source_inbound_email_id` is unique and is saved in the same transaction as the order. Production Graph calls ignore base-URL overrides and refuse http. Non-converted mail expires after 90 days. Pending attachment placeholders are retried and block conversion. Outbound customer mail can set `Reply-To` from `OUTBOUND_REPLY_TO`. Order notices are on the order. Welcome, set-password, and password-reset mail are on the account audit log. Replies to Launchpad and automatic replies are ignored. This feature contains no AI. Incoming email content is never sent automatically. `node scripts/verify-email-security.js` checks these guarantees.
